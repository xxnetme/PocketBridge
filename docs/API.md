# HTTP API — PocketBridge

Локальный HTTPS-сервер запускается на порту `8765` (настраивается в диапазоне `1024–65000`; при занятости пробуются следующие 15 портов). Принимаются подключения только из локальных сетей (loopback, RFC 1918, CGNAT `100.64.0.0/10`, IPv6 ULA и link-local).

## Авторизация

- Все запросы к `/api/*` требуют заголовок:
  ```http
  X-Access-Key: <код с экрана телефона>
  ```
  При неверном или отсутствующем ключе возвращается `403 Forbidden`.
- `GET /` (веб-интерфейс) доступен без ключа; автоматический вход по ссылке `/#k=<код>` выполняется на стороне браузера.
- `GET /thumb` авторизуется параметром `?token=<сессионный токен>` (выдаётся через `POST /api/session`).
- `GET /preview` и `GET /dl` авторизуются одноцелевыми временными тикетами `?ticket=<id>` (TTL 10 минут).
- `/dav/*` использует стандартную HTTP Basic-авторизацию (логин любой, пароль — код доступа); `OPTIONS /dav/` открыт без авторизации для совместимости с клиентами ОС.

## Диагностика сервера

События сетевого обработчика и службы Android записываются в `logcat` с тегом `WiFiFiles`: фиксированный код и тип исключения, например `TLS_REJECTED [SSLHandshakeException]`. `REQUEST_FAILED` относится к обработке соединения, `ACCEPT_FAILED` — к приёму соединения; `SERVER_START_FAILED`, `FOREGROUND_START_FAILED` и `WIFI_LOCK_FAILED` относятся к запуску или удержанию службы. URL, параметры, заголовки, тела и исходные сообщения исключений в эти записи не передаются. Это не журнал запросов. Коды и тексты ответов API и WebDAV не меняются.

Перед передачей полного отчёта Android или журнала браузера проверьте его отдельно: диагностические данные ОС, отчёт о сбое приложения и логи клиента не проходят через этот серверный регистратор.

## Общий корень и режим доступа

Все `path`, `base`, `dest` и WebDAV-пути относительны к выбранной на телефоне папке, которая отображается как `/`. Абсолютный путь на телефоне не публикуется. Смена корня или режима завершает текущую сессию: код доступа, сессионные токены и ссылки нужно получить заново.

В режиме «Только чтение» сервер блокирует изменения после проверки кода (`403 Forbidden`, `X-PocketBridge-Read-Only: 1`), в том числе запись файлов и буфера обмена из браузера. Доступны чтение и POST для просмотра и скачивания (`session`, `preview-ticket`, `download-ticket`, `zip-ticket`, `download-zip`), а также запуск и отмена отчёта (`scan-start`, `scan-cancel`). Корзина и черновики загрузки в этом режиме недоступны, включая `GET /api/trash` и `GET /api/upload-status`. `GET /api/text` возвращает `X-File-Editable: 0`. WebDAV рекламирует `OPTIONS, GET, HEAD, PROPFIND`; остальные методы после авторизации получают `403`.

## Просмотр каталогов и поиск

### `GET /api/list?path=/`
Возвращает содержимое каталога (папки идут первыми; временные `.wifi-upload-*.part`, `.pocketbridge-uploads`, `.pocketbridge-trash` и символические ссылки не включаются в список).

```json
{
  "path": "/",
  "readOnly": false,
  "uploadScope": "573cad8a-2280-489c-8c4b-b5bc80a5ded0",
  "totalBytes": 128000000000,
  "freeBytes": 54200000000,
  "clipHasText": false,
  "clipUpdatedAt": 0,
  "quickDirs": ["/DCIM/Camera", "/Pictures", "/Download", "/Documents", "/Music"],
  "items": [
    {"name": "Фото", "path": "/Фото", "dir": true, "size": 0, "modified": 1731798000000},
    {"name": "заметки.md", "path": "/заметки.md", "dir": false, "size": 2048, "modified": 1731798720000}
  ]
}
```
`readOnly` обозначает ограничения текущей сессии. `uploadScope` — непрозрачный ID области для докачки; возвращается только при разрешённой записи и доступном журнале. Это не код доступа. Поле `quickDirs` возвращается только для корня (`/`) и содержит реально существующие стандартные каталоги и `/PocketBridge Inbox`, если он создан внутри общей папки.

### `GET /api/search?path=/&q=текст`
Поиск в `path`, рекурсивно по умолчанию (`deep=0` — только эта папка). NFC-нормализация, без символических ссылок и служебных файлов. Минимум 2 символа **или** хотя бы один фильтр:

| Фильтр | Значение |
| --- | --- |
| `after`, `before` | время изменения в миллисекундах Unix; `after` включительно, `before` не включается |
| `minBytes`, `maxBytes` | размер в байтах, обе границы включаются; каталоги при фильтре размера не выдаются |
| `type` | `all`, `folder`, `file`, `image`, `video`, `audio`, `document`, `archive`, `other` (по расширению) |
| `ext` | конкретное расширение, например `jpg` |

Лимит — 200 результатов, 50 000 объектов или 8 секунд. `truncated: true` означает неполный результат, в том числе при недоступных подпапках.

```json
{"items": [...], "truncated": false}
```

### `GET /api/size?path=/Фото`
Подсчитывает суммарный размер файлов в каталоге (лимит — 200 000 узлов или 30 секунд).

```json
{"bytes": 15420912, "partial": false}
```

## Управление файлами и папками

### `POST /api/mkdir?path=/&name=Новая`
Создаёт папку внутри `path`. При конфликте имени — `409 Conflict`.

### `POST /api/mkdirs?path=/Фото/2026/Отпуск`
Рекурсивно создаёт цепочку вложенных папок (идемпотентно). Если сегмент занят файлом — `409 Conflict`.

### `POST /api/rename?path=/старое.txt&name=новое.txt`
Переименовывает файл или папку в пределах текущего каталога (`name` без `/` и `\`, до 200 символов). При занятом имени — `409 Conflict`.

### `POST /api/copy?path=/a.txt&dest=/Архив&name=копия.txt&overwrite=0&unique=0`
Рекурсивно копирует файл или папку в каталог `dest` (поддерживается и синоним `to`):
- `name` *(необязательно)* — новое имя в папке назначения;
- `overwrite=1` — заменить существующий однотипный объект;
- `unique=1` — автоматически подобрать свободное имя вида `имя (1).ext`;
- без `overwrite`/`unique` при конфликте возвращается `409 Conflict`.
Запрещено копирование корня `/`, символических ссылок и копирование папки внутрь самой себя (лимит — глубина 40, до 50 000 объектов).

```json
{"ok": true, "name": "копия.txt", "path": "/Архив/копия.txt", "dir": false}
```

### `POST /api/move?path=/a.txt&dest=/Архив&name=новое.txt&overwrite=0&unique=0`
Перемещает файл или папку в каталог `dest` (атомарный `rename`/`Files.move` с автоматическим откатом на копирование + удаление при переносе между файловыми системами). Параметры и проверки конфликтов аналогичны `/api/copy`.

### `POST /api/delete?path=/файл.txt`
Перемещает файл или папку со всем содержимым в корзину общего корня, без копирования с последующим удалением. Возвращает запись (`ok`, `id`, `path`, `name`, `dir`, `size`, `deletedAt`, `expiresAt`). Корень `/`, ссылка и служебные объекты не удаляются. Если корзина недоступна или заполнена, источник остаётся на месте. WebDAV `DELETE` использует ту же корзину.

- `GET /api/trash` → `{items, usedBytes, limitBytes, ttlMillis}`. Хранение до 7 дней, до 20 ГиБ и 512 объектов на общий корень; одна папка — до 50 000 вложенных объектов. Истёкшие записи убираются при работе сервера с этим корнем.
- `POST /api/trash-restore?id=<id>[&path=/Папка][&name=новое]` → `{path}`. По умолчанию исходный путь, родитель должен существовать. При конфликте возвращает `409` и ничего не перезаписывает.
- `POST /api/trash-purge?id=<id>` → `{ok:true}`: безвозвратное удаление **одной** записи.

### Пакетное переименование

`POST /api/rename-preview` принимает JSON `{paths: ["/a.txt", "/b.txt"], template: "Фото_{n:3}{ext}", start: 1}` (2–200 объектов). Токены: `{name}` (имя без расширения), `{ext}` (с точкой), `{n}`, `{n:1}`…`{n:6}`. Порядок путей задаёт нумерацию. Ответ `{items:[{path,name,newName,error}],previewId}`. При коллизии `previewId: null`. Имена уже существующих объектов, включая участвующие в той же операции, не заменяются; смена имён по циклу не поддерживается.

`POST /api/rename-apply?id=<previewId>` применяет одноразовый предпросмотр (5 минут), повторно проверяет источник и цель и возвращает `{renamed,failed,items}`. У каждой записи `status: renamed | unchanged | error`, для успеха — `newPath`. Ошибка одной записи не откатывает предыдущие изменения.

## Общий текстовый буфер обмена (ПК ↔ телефон)

### `GET /api/clipboard`
Возвращает текущий текст эфемерного буфера сессии (хранится только в ОЗУ и очищается при остановке сервера):
```json
{"text": "https://example.org", "updatedAt": 1731952800000, "source": "phone"}
```
`source` принимает значения `"web"`, `"phone"` или `""` (когда буфер пуст).

### `POST /api/clipboard`
Обновляет или очищает общий буфер (до 65 536 символов UTF-8; при превышении — `413 Payload Too Large`). Принимает `application/json` (`{"text": "..."}`) или `text/plain; charset=utf-8` (пустое тело очищает буфер). Возвращает актуальный объект буфера с `"ok": true`.

## Скачивание и ZIP-архивы

### `POST /api/download-ticket?path=/файл.bin`
Выдаёт временную ссылку для потокового скачивания браузером:
```json
{"url": "/dl?ticket=<id>"}
```

### `POST /api/zip-ticket?base=/`
Тело запроса (`application/json`):
```json
{"paths": ["/Фото", "/Документы/отчёт.docx"]}
```
Выдаёт `{"url": "/dl?ticket=<id>"}` для потокового скачивания ZIP-архива с сохранением структуры относительно `base`.

### `GET /dl?ticket=<id>`
Отдаёт файл (`Content-Disposition: attachment`, с поддержкой `Range` → `206 Partial Content` / `416 Range Not Satisfiable`) или потоковый ZIP (`Transfer-Encoding: chunked`). Принимает только тикеты типов `download` и `zip`.

### `GET /api/download?path=/файл.bin` и `POST /api/download-zip?base=/`
Прямое скачивание файла (с поддержкой `Range`) и потокового ZIP с заголовком `X-Access-Key`.

## Загрузка файлов и докачка

### Сохраняемая загрузка (браузер → Android)

`POST /api/upload-init?path=/&name=video.mp4&size=104857600&id=r<32hex>&sha256=<64hex>&scope=<uploadScope>` создаёт сохраняемый черновик. Браузер заранее считает SHA‑256 файла и сохраняет ID до запроса. Повтор с теми же ID, путём, именем, размером и SHA‑256 возвращает **тот же** черновик. `unique=1` подбирает свободное имя; `overwrite=1` допускает замену только явно выбранного и не изменившегося файла.

| Метод | Поведение |
| --- | --- |
| `GET /api/upload-status?id=…` | Возвращает `{uploadId,name,size,received,done,expiresAt,durable,chunk}`. `received` — подтверждённые байты. `404` не означает разрешение начать тот же черновик с нуля. |
| `POST /api/upload-chunk?id=…&offset=…` | `Content-Length`, от 1 байта до 4 МиБ. Успех — сохранены данные и смещение; неполная часть не засчитывается. При неверном смещении — `409` и `X-Upload-Received`. |
| `POST /api/upload-finish?id=…` | Полный размер и SHA‑256 проверяются потоково. Идемпотентный ответ при уже состоявшейся публикации. `409` с `X-PocketBridge-Upload-Conflict: 1` — конфликт назначения, данные черновика остаются. |
| `POST /api/upload-retarget?id=…&name=новое` | Меняет имя в той же папке, сохраняя байты. `overwrite=1` — новое явное подтверждение замены. |
| `POST /api/upload-abort?id=…` | Удаляет незавершённый черновик; готовый файл не удаляется (`done: true`, если уже сохранён). |

Лимиты: до 20 ГиБ на файл и в сумме для сохранённых активных черновиков приложения, до 32 активных черновиков, запас 32 МиБ, TTL 24 часа от последней подтверждённой части. HTTP `429` — квота, `507` — нехватка места. Истёкшие данные убираются при следующем запуске доступа с записью к этому корню и периодически во время его работы. Новая сессия требует актуального кода; черновик привязан к прежней общей папке. Метаданные хранятся в приватной области приложения, данные — на томе хранилища. При остановленной вкладке передача не идёт.

### Совместимый чанковый режим

`POST /api/upload-init` **без** `id`, `sha256`, `scope` — прежний эфемерный режим (им пользуется загрузка дерева папок). Далее `upload-status`, `upload-chunk` (до 32 МиБ), `upload-finish`, `upload-abort` с полученным ID. Он не переживает остановку сервера и не проверяет полный хеш. Лимит — 32 незавершённые загрузки на экземпляр сервера, отдельно от сохраняемых черновиков. При заполнении новый старт получает `429` до создания `.part`; освобождение слота — при завершении, отмене, невосстановимой ошибке или через 6 часов от старта. Обычный сетевой обрыв не отменяет загрузку: проверяйте `upload-status`.

### `POST /api/upload?path=/&name=file.txt&overwrite=0&unique=0`
Однозапросная загрузка сырого тела файла с `Content-Length` (до 20 ГБ) через временный `.part`-файл.

## Предпросмотр и миниатюры

### `POST /api/session`
Выдаёт токен только для миниатюр; требуется действующий `X-Access-Key`:
```json
{"token": "<32 hex>", "ttl": 7200000}
```
При 16 действующих токенах новый получает `429 Too Many Requests` с `Retry-After` в секундах до ближайшего ожидаемого освобождения слота. Уже выданные токены не отзываются. Чтобы продлить срок **своего действующего** токена без нового слота, передайте его в `X-PocketBridge-Session`. Просроченный или неизвестный токен не возобновляется: при наличии места выдаётся новый. Без миниатюр списки, просмотр файлов и передачи продолжают работать.

### `GET /thumb?token=<token>&path=/Фото/img.jpg&w=320`
- Для растровых изображений и видео возвращает `image/jpeg` (ширина ограничена 64–512 px, кешируется на диске до 200 МБ).
- Для `.svg` (до 5 МБ) возвращает `image/svg+xml` с `Content-Security-Policy: default-src 'none'; ...; sandbox`.

### `POST /api/preview-ticket?path=/Фото/img.jpg` → `GET /preview?ticket=<id>`
Выдаёт `{"url": "/preview?ticket=<id>", "mime": "..."}` для inline-просмотра изображений, SVG (до 5 МБ, с `sandbox` CSP), аудио, видео и PDF (с поддержкой `Range`). Форматы HEIC/RAW (`.heic/.heif/.dng/.cr2/.nef/.arw/.raf`, до 50 МБ) перекодируются на лету в JPEG (до 2400 px, качество 82). Тикеты `preview` действительны только для `/preview`.

### `GET /api/text?path=/заметки.md`
Возвращает UTF-8 текст для `.txt`, `.md`, `.csv`, `.log`, `.json`, `.xml`, `.html`, `.htm`, `.css`, `.js` размером до 5 МБ.

### `GET /api/docx?path=/отчёт.docx`
Извлекает текст из `word/document.xml` (до 8 МБ XML, до 1 000 000 символов, документы с DTD отклоняются):
```json
{"text": "...", "truncated": false}
```

## WebDAV (`/dav`)

Поддерживаются методы `OPTIONS`, `PROPFIND` (`Depth: 0` и `Depth: 1`), `GET` (включая `Range`), `HEAD`, `PUT` (`Content-Length` и `Transfer-Encoding: chunked`, до 20 ГБ), `MKCOL`, `DELETE`, `MOVE`, `COPY` (с заголовком `Overwrite: T|F`), `PROPPATCH`, `LOCK`, `UNLOCK`. Подробнее — в [WEBDAV.md](WEBDAV.md).

### `POST /api/save-text`
Атомарное создание (`create=1&path=<dir>&name=<file>`) или сохранение (`path=<file>&expectedModified=<ms>`) текстового файла в UTF-8 (тело запроса до 2 МБ; флаги `overwrite=1`, `unique=1`, `force=1`). При внешнем изменении файла возвращает `409` с заголовками `X-Conflict-Reason: mtime` и `X-File-Modified`. Ответ: `{"ok": true, "name": "...", "path": "...", "size": 128, "modified": 1700000000000}`. `GET /api/text` дополнительно возвращает `X-File-Modified`, `X-File-Size` и `X-File-Editable: 1|0`.

### `POST /api/rotate-image?path=<path>&degrees=90|180|270`
Поворачивает JPEG, PNG или WebP (до 40 МБ и 36 МП, с учётом текущей EXIF-ориентации) с атомарной перезаписью и обновлением `lastModified`. Ответ: `{"ok": true, "path": "...", "width": 1200, "height": 1600, "size": ..., "modified": ...}`.

### `GET /api/zip-list?path=<zip>` и `POST /api/zip-extract`
- `GET /api/zip-list` — чтение каталога `.zip` без распаковки (UTF-8 с авто-fallback на `CP866`/ISO-8859-1): `fileCount`, `dirCount`, `unsafeCount`, `totalUncompressed`, `truncated` и массив `entries` (до 2 000 элементов).
- `POST /api/zip-extract?path=<zip>&dest=<dir>&subfolder=1|0[&overwrite=1][&unique=1]` — полная или выборочная распаковка (необязательное JSON-тело `{"entries": ["docs/plan.md", ...]}`). Блокирует Zip Slip (`..`, `\`, абсолютные пути, диски Windows), симлинки в пути назначения и Zip Bomb (лимит 10 000 объектов, глубина 32, 2 ГБ суммарно, степень сжатия > 100:1 для файлов свыше 10 МБ).

### `GET /api/stat?path=<path>` и `GET /api/hash?path=<path>`
- `GET /api/stat` — подробные метаданные файла или папки (`name`, `path`, `parent`, `dir`, `size`, `modified`, `readable`, `writable`, `hidden`, для папок `directFiles`/`directDirs`, для файлов `ext`/`mime`, для изображений `width`/`height`/`exifOrientation`).
- `GET /api/hash` — потоковый расчёт `SHA-256` файла (буфер 64 КБ, файлы до 4 ГБ): `{"algo": "SHA-256", "sha256": "<64-hex>", "size": ..., "modified": ...}`.

## Проверка папок и дубликаты

- `POST /api/scan-start?mode=manifest|compare|duplicates&path=/Фото[&other=/Копия]` запускает фоновое чтение в рамках текущего слушателя. `other` обязателен для сравнения двух папок. Ответ содержит `id`, `state`, `phase`, `found`, `checked`, `bytes`, `skipped`.
- `GET /api/scan?id=…[&result=1]` — прогресс и, по запросу, готовый результат. `state`: `running`, `done`, `cancelled`, `error`. `POST /api/scan-cancel?id=…` отменяет выполнение.
- `manifest` возвращает `{format:"pocketbridge-sha256-v1",root,files:[{path,size,sha256}]}`; `path` внутри `files` относителен проверенной папке. Это тот же формат, что браузер сохраняет на диск для сравнения с другой копией.
- `compare` возвращает `{same,items:[{path,state}]}` по относительному пути. Отличия: `missing`, `changed`, `added` относительно первой папки.
- `duplicates` возвращает `{groups:[{size,sha256,paths}]}`, где `paths` — виртуальные пути от общей папки. Совпадение размера — только предварительный фильтр. `POST /api/duplicate-trash?id=…&path=…&keep=…` отправляет одну подтверждённую копию в корзину, если другая из той же группы ещё существует без изменений. Сканирование ничего не удаляет.

По одной активной проверке, до 20 000 файлов, 100 000 узлов, 128 ГиБ прочитанных данных или 20 минут; лимит `/api/hash` (4 ГиБ) не используется. Готовые отчёты остаются в памяти до 15 минут (до двух последних) и сбрасываются при остановке. Символические ссылки и специальные файлы не хешируются; ошибки файлов не выдаются за совпадение. Это проверка файлов, а не атомарный снимок изменяемого каталога.

## Лимиты

| Параметр | Значение |
| --- | --- |
| Параллельные рабочие потоки | до 32 (при переполнении — `503`) |
| Сессии `/thumb` | до 16 активных, TTL 2 часа |
| Тикеты `/preview` и `/dl` | до 256 активных, TTL 10 минут |
| Сохраняемые загрузки | до 32, TTL 24 часа от прогресса, чанк до 4 МиБ |
| Эфемерные чанковые загрузки | до 32, TTL 6 часов, чанк до 32 МиБ |
| Максимальный размер загружаемого файла | 20 ГиБ |
| Кеш миниатюр (фото + кадры видео) | 200 МБ (автоочистка старейших файлов) |
| Превью HEIC/RAW / текста и SVG / DOCX XML | 50 МБ / 5 МБ / 8 МБ |
| Редактор текста (`/api/save-text`) | до 2 МБ (UTF-8) |
| Поворот фото (`/api/rotate-image`) | JPEG/PNG/WebP до 40 МБ и 36 МП |
| Скачивание в ZIP | до 500 выбранных объектов, до 5 000 файлов, глубина до 40 |
| Просмотр / распаковка `.zip` | до 2 000 показанных записей / до 10 000 объектов, 2 ГБ, глубина 32 |
| Расчёт `SHA-256` (`/api/hash`) | файлы до 4 ГБ (потоково, буфер 64 КБ) |
